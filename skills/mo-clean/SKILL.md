# mo clean

只负责 `mo clean` 的 agent 操作。技能被加载不等于获得删除授权；沿用用户已明确给出的范围，不顺带卸载应用、优化系统、更新工具或执行其他清理子命令。

## 核对安装版与范围

```sh
command -v mo
mo --version
mo clean --help
```

以当前安装版帮助为准。找不到 `mo` 时说明缺少工具，不自动安装。核对用户授权的是常规本机清理，还是指定外置卷的系统元数据清理。

`mo clean` 不是任意目录删除器，也不能仅凭当前工作目录限定清理范围。用户只允许清理某个目录或某类数据时，先确认现有保护机制能否满足该边界；无法满足则停止执行，不扩大成整机清理。

常用参数：

| 命令 | agent 用途 |
| --- | --- |
| `mo clean --dry-run` | 预览本机清理，不删除目标内容；可简写为 `-n`。 |
| `mo clean --whitelist` | 交互管理需要保留的路径。 |
| `mo clean` | 实际执行已获授权的本机清理。 |
| `mo clean --debug --dry-run` | 需要诊断候选或跳过原因时增加日志。 |
| `mo clean --external "/Volumes/Example" --dry-run` | 仅预览指定已挂载外置卷上的系统元数据清理。 |
| `mo clean --external "/Volumes/Example"` | 按相同外置卷范围实际执行。 |

不要假设存在 `--yes`、路径位置参数或分类选择参数。例如，Mole 1.62.0 不支持 `--yes`，并已移除 `--select`、`--categories`、`--exclude`；不要把其他子命令的参数套给 clean。

## 预览与保护名单

先说明用户授权范围，并确定需要保留的内容，再运行对应的 `--dry-run`。保留候选、估算大小、跳过项和权限限制；预览可能写入清单及日志，不应称为完全无文件写入。

**实际 clean 是永久删除，默认会清空 `~/.Trash`。** 用户要求保留废纸篓，或已有授权尚未覆盖永久清空它时，通过 `mo clean --whitelist` 保护 Trash 后重新预览；用户明确要求清空时，按该授权处理。不要把 clean 当作“移入废纸篓”的可恢复操作。

保护名单操作要点：

- 使用真实终端打开 `mo clean --whitelist`，读取当前菜单，只调整本次需要保留的项目，按菜单提示保存。
- 选择会持久写入 `~/.config/mole/whitelist`。保留已有条目，报告本次新增或调整的保护规则，不直接用少量自定义路径覆盖整份文件。
- 需要追加自定义路径时，先通过菜单保存现有选择，再按安装版文档支持的格式逐行追加。存在配置文件会替代可选默认项，不能假设未列出的默认项仍受保护。
- 保护名单无法读取时停止，不删除配置、放宽权限或绕过保护来继续。

本机预览通常写入 `~/.config/mole/clean-list.txt`。检查清单，但不要把它当作可编辑的执行 allowlist；真正执行会重新扫描。保护名单或授权范围变更后重新预览。指定外置卷时，先用只读路径与挂载信息确认实际卷，避免错用同名或未挂载目录。

## 执行与交互

执行前向用户交代拟清内容、估算大小、保留项，以及是否会永久清空废纸篓。复用已有明确授权；仅对尚未覆盖的永久删除影响、废纸篓清空或系统级操作取得具体确认，不重复询问同一项已获授权的动作。纯预览请求只运行预览。

运行与预览相同范围的 `mo clean`，去掉 `--dry-run` 即进入真实删除。没有 TTY 不代表工具会等待确认，不要用管道自动回答所有提示，也不要编造无人值守参数。

以普通用户运行，不使用 `sudo mo clean`。工具需要系统缓存权限时会自行提示：

- 本次未授权系统级清理时，按实际菜单选择跳过；当前版本提示中 Space 是跳过。
- 已授权且需要认证时，让用户接手输入，不读取、传递或记录管理员密码；无法完成交互就保留系统部分未执行的状态。
- 有效的既有 sudo 会话会让工具直接启用系统清理，TTY 和非交互模式都可能发生。若授权明确限于用户级，而预览显示系统权限已可用，当前版本又没有仅用户级开关，则停在预览阶段，说明无法保证范围；不要通过撤销认证、换身份或修改工具来绕过。不能把“没有出现密码提示”当作新授权。

尊重工具对繁忙应用、受保护路径和权限不足项的跳过或拒绝。不停止用户应用、不改 ACL、不授予更广权限，也不用直接删除命令绕过失败项。命令中断、超时或结果不完整时，先核对已完成部分与日志，不盲目整轮重跑。

## 核对与回报

记录真实退出码、完成摘要、已清理项、跳过/失败项和未执行的系统部分。默认操作日志位于 `~/Library/Logs/mole/operations.log`；按本次运行定位相关记录，不输出凭据或无关私人信息。

清理前后对同一卷采样，例如本机清理使用 `df -k "$HOME"`，外置卷使用其确切挂载路径。分别报告工具的清理量/大小估算和观测到的可用空间变化：硬链接、APFS 共享块、快照及并发活动会造成差异，不能把估算值全部算作实际回收空间。

只声称回执能够证明的结果。预览完成、部分清理和全部授权范围执行完成要分开；正常退出也不表示所有被跳过的项目已清理。
